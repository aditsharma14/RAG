# Multimodal RAG: Answering Questions from a PDF's Text *and* Images

This folder covers **multimodal RAG**: retrieval-augmented generation over a PDF that contains both text and images. Every earlier folder threw images away at the loading step; here a chart is a first-class piece of the knowledge base. It can be **retrieved** by a text question and **read** by the LLM.

Two models make this possible:

- **CLIP** (`openai/clip-vit-base-patch32`, a free Hugging Face model that runs locally) turns text **and** images into vectors in the **same 512-number space**, so the question *"What does the chart show about revenue?"* can land next to a picture of a bar chart.
- A **vision LLM** (`qwen/qwen3.8-27b` on Groq) receives the retrieved text chunks **and the actual images**, and answers by looking at the chart.

The notebook builds the pipeline in seven steps:

1. **Sample PDF**: if `multimodal_sample.pdf` is missing, it's generated: one page with a short revenue summary and a Q1/Q2/Q3 bar chart.
2. **Models**: CLIP for embeddings, Qwen on Groq for answers.
3. **Embedding functions**: `embed_text()` and `embed_image()`, both returning unit-length 512-d CLIP vectors.
4. **Process the PDF**: PyMuPDF pulls out each page's text (split into chunks) and each embedded image (embedded with CLIP and kept as base64).
5. **One FAISS index** holding text and image vectors side by side, built from the precomputed vectors.
6. **Multimodal message**: the question, the retrieved text and the retrieved images packed into one `HumanMessage`.
7. **Pipeline**: retrieve → build message → ask the vision LLM, run on three example questions.

```
Multi-Model/
├── code.ipynb              # Notebook: CLIP embeddings for text + images → FAISS → Groq vision LLM
├── multimodal_sample.pdf   # 1 page: revenue summary text + bar chart (generated by Cell 1 if missing)
└── readme.md               # This file
```

## 1. Core Concepts

### The problem: text-only RAG is blind to images
A text loader reads a PDF page and returns its text. The chart on the page is simply dropped. Our sample page says *"As illustrated in the chart below, revenue grew steadily..."*, but the numbers (≈ $120K, $180K, $310K) only exist **inside the image**. A text-only pipeline can never answer *"How much revenue was there in Q3?"*.

Multimodal RAG needs two things text RAG doesn't:
1. A way to **retrieve** images with a text question.
2. An LLM that can **read** the images it is given.

### CLIP: one vector space for text and images
**Definition:** CLIP (Contrastive Language–Image Pre-training, OpenAI 2021) is a model with two encoders, one for text and one for images, trained on 400 million image–caption pairs so that an image and a caption that describes it end up with **similar vectors**.

```
 "a bar chart of quarterly revenue" ──► CLIP text encoder  ──► [0.02, -0.01, ...]  ┐
                                                                                  ├─ close together
          [image of a bar chart]    ──► CLIP image encoder ──► [0.01, -0.02, ...]  ┘
```

Both encoders end in a projection to **512 numbers**. Because the spaces are shared, a single vector index can hold text chunks and images, and one text query can search both.

`all-MiniLM-L6-v2`, used in every other folder, understands text much better than CLIP's text encoder does, but it can't embed images at all. That trade-off is discussed in [Section 6](#6-limitations-and-tips).

### Vision LLM
**Definition:** A chat model that accepts images as part of the input message, alongside text. In LangChain an image is passed as a content block:

```python
{"type": "image_url", "image_url": {"url": "data:image/png;base64,iVBORw0KGgo..."}}
```

The image is sent **inline as base64 text** (a `data:` URL), so nothing has to be uploaded anywhere first. This is why the notebook keeps a base64 copy of every image: the CLIP vector is enough to *find* the image, but the LLM needs the image itself to *read* it.

### The full pipeline

```
                ┌──────────── INDEXING (once) ─────────────┐
PDF ──► PyMuPDF ┬─► page text ──► split ──► CLIP text  ──┐ │
                │                                        ├─┼─► FAISS (512-d, text + images)
                └─► images ──┬─► CLIP image ─────────────┘ │          │
                             └─► base64 ──► image_data_store │          │
                └──────────────────────────────────────────┘          │
                                                                      │
question ──► CLIP text ──► similarity_search_by_vector ◄──────────────┘
                                   │
                text chunks ───────┤
   image_id ──► image_data_store ──┤ (base64 images)
                                   ▼
             HumanMessage[question, text excerpts, images] ──► Qwen (Groq) ──► answer
```

### Why images go into the store as placeholders
A FAISS store holds `Document`s, and a `Document` needs text. An image is stored as a placeholder document:

```python
Document(page_content="[Image: page_0_img_0]",
         metadata={"page": 0, "type": "image", "image_id": "page_0_img_0"})
```

Its **vector** is the CLIP image embedding; its **text** is just a label. After retrieval, `metadata["type"]` tells the code whether a hit is text or an image, and `metadata["image_id"]` is the key for looking up the real image in `image_data_store`.

### Multimodal vs text-only RAG

| | Text-only RAG | Multimodal RAG (this folder) |
|---|---|---|
| What gets indexed | Text chunks | Text chunks + images |
| Embedding model | Text model (e.g. `all-MiniLM-L6-v2`, 384-d) | CLIP (512-d, shared text/image space) |
| What the LLM sees | Text | Text + images |
| LLM | Any chat model | Must accept images (vision model) |
| Questions about charts, diagrams, photos | ❌ | ✅ |
| Text retrieval quality | Good | Weaker (CLIP's text encoder is small and reads only 77 tokens) |
| Cost per question | Text tokens | Text tokens + image tokens (images are expensive) |

## 2. Use Cases

Multimodal RAG helps when **the answer lives in a picture**:

- **Financial and business reports**: revenue charts, KPI dashboards, tables saved as images.
- **Technical manuals**: wiring diagrams, exploded views, screenshots of settings screens.
- **Scientific papers**: plots, figures and their captions.
- **Slide decks exported to PDF**: much of the content is diagrams with a few words.
- **Medical, insurance, real estate documents**: scans, photos and forms next to the text that describes them.
- **Product catalogues**: *"Show me the model with the blue handle"* matched against product photos.

It is **less useful** when:
- The images are decorative (logos, stock photos). They take up retrieval slots and image tokens for nothing.
- The PDF is a **scan**. The whole page is one image, and `get_text()` returns nothing; you need OCR (see the [DataParsing](../DataParsing/readme.md) folder) or a page-as-image approach.
- The answer is in long passages of text. A text embedding model retrieves those better than CLIP.

### Cell 3: Embedding functions

```python
def embed_image(image_data):
    if isinstance(image_data, str):
        image = Image.open(image_data).convert("RGB")
    else:
        image = image_data

    inputs = clip_processor(images=image, return_tensors="pt")
    with torch.no_grad():
        features = clip_model.get_image_features(**inputs).pooler_output
    features = features / features.norm(dim=-1, keepdim=True)
    return features.squeeze().numpy()


def embed_text(text):
    inputs = clip_processor(text=text, return_tensors="pt", padding=True,
                            truncation=True, max_length=77)
    with torch.no_grad():
        features = clip_model.get_text_features(**inputs).pooler_output
    features = features / features.norm(dim=-1, keepdim=True)
    return features.squeeze().numpy()
```

| Line | What it does |
|---|---|
| `isinstance(image_data, str)` | Accepts either a file path or an already-open PIL image. |
| `clip_processor(images=..., return_tensors="pt")` | Resizes and crops the image to 224×224 and normalizes the pixels into a PyTorch tensor. |
| `torch.no_grad()` | No gradients needed for inference; saves memory and time. |
| `.pooler_output` | **Needed in transformers 5.** `get_image_features` / `get_text_features` now return an output object, not a tensor. `.pooler_output` holds the final projected 512-d vector (the same values as `model(...).text_embeds` before normalization). Older course code without it fails on `.norm()`. |
| `features / features.norm(...)` | Scales each vector to length 1. Then the dot product of two vectors equals their cosine similarity, and text and image vectors are on the same scale. |
| `.squeeze().numpy()` | Turns shape `(1, 512)` into a plain NumPy array of 512 numbers. |
| `truncation=True, max_length=77` | CLIP's text encoder reads at most **77 tokens**. Anything longer is cut off silently. |

### Cell 4: Process the PDF

```python
doc = pymupdf.open(pdf_path)
all_docs = []
all_embeddings = []
image_data_store = {}
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=100)

for i, page in enumerate(doc):
    text = page.get_text()
    if text.strip():
        temp_doc = Document(page_content=text, metadata={"page": i, "type": "text"})
        for chunk in splitter.split_documents([temp_doc]):
            all_embeddings.append(embed_text(chunk.page_content))
            all_docs.append(chunk)

    for img_index, img in enumerate(page.get_images(full=True)):
        try:
            xref = img[0]
            image_bytes = doc.extract_image(xref)["image"]
            pil_image = Image.open(io.BytesIO(image_bytes)).convert("RGB")
            image_id = f"page_{i}_img_{img_index}"
            ...
            image_data_store[image_id] = base64.b64encode(buffered.getvalue()).decode()
            all_embeddings.append(embed_image(pil_image))
            all_docs.append(Document(page_content=f"[Image: {image_id}]",
                                     metadata={"page": i, "type": "image", "image_id": image_id}))
        except Exception as e:
            print(f"Error processing image {img_index} on page {i}: {e}")
doc.close()
```

Three containers are filled in parallel:

| Container | Holds | Used by |
|---|---|---|
| `all_docs` | `Document`s: text chunks and image placeholders | FAISS (text + metadata) |
| `all_embeddings` | One CLIP vector per document, **in the same order** | FAISS (vectors) |
| `image_data_store` | `image_id` → base64 PNG | The LLM message (Cell 7) |

**Text, per page:**
- `page.get_text()` returns the page's text in reading order.
- The page text is wrapped in a temporary `Document` with `{"page": i, "type": "text"}` so the splitter copies that metadata onto every chunk.
- Each chunk is embedded with CLIP's **text** encoder.

**Images, per page:**
- `page.get_images(full=True)` lists the images on the page. `img[0]` is the **xref**, PDF's internal ID for the image object.
- `doc.extract_image(xref)["image"]` returns the raw image bytes in their original format (PNG, JPEG...).
- The image is converted to RGB and re-saved as **PNG**, so every image can be sent as `data:image/png;base64,...`.
- The image is embedded with CLIP's **image** encoder, and a placeholder `Document` is added.
- `try/except` skips images PyMuPDF can't decode (rare formats, masks) instead of stopping the whole loop.

Output: **2 documents**, one text chunk (the whole page text, 365 characters, fits in one 500-character chunk) and one image (`page_0_img_0`).

### Cell 5: Build the FAISS index

```python
embeddings_array = np.array(all_embeddings)
print(embeddings_array.shape)   # (2, 512)

vector_store = FAISS.from_embeddings(
    text_embeddings=[(d.page_content, emb) for d, emb in zip(all_docs, embeddings_array)],
    embedding=None,
    metadatas=[d.metadata for d in all_docs],
)
```

| Argument | What it does |
|---|---|
| `text_embeddings` | A list of `(text, vector)` pairs. FAISS stores the vector as-is instead of embedding the text itself. |
| `embedding=None` | Normally the embedding model used for queries. There isn't one here, because queries are embedded by hand in Cell 6 and searched with `similarity_search_by_vector`. Calling `similarity_search("text")` on this store would fail. |
| `metadatas` | Keeps `page`, `type` and `image_id` for every entry. |

The warning *"`embedding_function` is expected to be an Embeddings object"* comes from `embedding=None` and can be ignored.

---

### Cell 6: Retrieval

```python
def retrieve_multimodal(query, k=5):
    query_embedding = embed_text(query)
    return vector_store.similarity_search_by_vector(embedding=query_embedding, k=k)
```

The question is embedded with CLIP's **text** encoder and compared against every vector in the store, text and image alike. FAISS's default distance is L2 (Euclidean); for unit-length vectors, a smaller L2 distance means a higher cosine similarity, so the ranking is the same.

With only 2 documents in the store, `k=5` simply returns both.

### Cell 7: Build the multimodal message

```python
def create_multimodal_message(query, retrieved_docs):
    content = [{"type": "text", "text": f"Question: {query}\n\nContext:\n"}]
    text_docs = [d for d in retrieved_docs if d.metadata.get("type") == "text"]
    image_docs = [d for d in retrieved_docs if d.metadata.get("type") == "image"]

    if text_docs:
        text_context = "\n\n".join(f"[Page {d.metadata['page']}]: {d.page_content}" for d in text_docs)
        content.append({"type": "text", "text": f"Text excerpts:\n{text_context}\n"})

    for d in image_docs:
        image_id = d.metadata.get("image_id")
        if image_id in image_data_store:
            content.append({"type": "text", "text": f"\n[Image from page {d.metadata['page']}]:\n"})
            content.append({"type": "image_url",
                            "image_url": {"url": f"data:image/png;base64,{image_data_store[image_id]}"}})

    content.append({"type": "text", "text": "\n\nPlease answer the question based on the provided text and images."})
    return HumanMessage(content=content)
```

The message is a **list of content blocks**, in this order:

```
[text]  Question: What does the chart on page 1 show...?  Context:
[text]  Text excerpts:  [Page 0]: Annual Revenue Overview ...
[text]  [Image from page 0]:
[image] data:image/png;base64,iVBORw0KGgo...
[text]  Please answer the question based on the provided text and images.
```

- Retrieved docs are split by `metadata["type"]`. Text is joined into one block, tagged with its page.
- Each image gets a short text label before it, so the LLM can tell which page it came from.
- The image placeholder text `"[Image: page_0_img_0]"` is **never** sent; it is only used to look up the real image.

## 6. Limitations and Tips

- **CLIP reads only 77 tokens of text.** A 500-character chunk is around 100–120 tokens, so the end of longer chunks is cut off before embedding. Use `chunk_size` around 250–300 for real documents.
- **Text and image scores aren't on the same scale.** CLIP's text-to-text similarities are typically much higher than its text-to-image ones (the "modality gap"). On a real PDF with dozens of chunks, text crowds images out of the top-k. That doesn't show here only because the store has 2 entries. Fix: search text and images separately (e.g. top-3 text + top-2 images) and merge.
- **CLIP is a weak text retriever.** For text chunks, a dedicated text model (`all-MiniLM-L6-v2` or better) retrieves much better. A common design is **two indexes**: a text model for text, CLIP for images, searched separately and merged.
- **Alternative: describe images with the LLM.** Instead of CLIP, ask the vision LLM to write a caption or summary for each image at indexing time, and index that text with a normal text embedding model. The original image is still sent at answer time. This retrieves charts by their *content* ("Q3 revenue $310K"), which CLIP can't read.
- **Images are expensive.** Each image adds hundreds or thousands of tokens to the request. Resize large images before base64-encoding, skip tiny ones (icons, logos), and cap how many images go into one message.
- **Scanned PDFs have no text and one big image per page.** `get_text()` returns empty and the "image" is the whole page. Use OCR, or render each page as an image (`page.get_pixmap()`) and treat pages as the unit.
- **Vector graphics are invisible to `get_images()`.** Charts drawn as PDF vector paths (common in exports from Excel or PowerPoint) are not image objects. Render the page or the chart's area with `page.get_pixmap(clip=rect)` to capture them.
- **`embedding=None` means text search on the store doesn't work.** Always search with `similarity_search_by_vector(embed_text(query))`. Wrapping `embed_text` in a small `Embeddings` class would remove the warning and allow `as_retriever()`.
- **Everything is in memory.** `image_data_store` and the FAISS index disappear when the kernel restarts. For real use, save the index (`vector_store.save_local(...)`) and the images to disk.
- **Check the model list.** Groq adds and retires vision models; if `qwen/qwen3.8-27b` disappears, list the current models at `https://api.groq.com/openai/v1/models` and pick one that accepts images.

## 8. Quick Glossary

| Term | Meaning |
|---|---|
| **Multimodal RAG** | RAG whose knowledge base and LLM input include more than text: here, images from a PDF |
| **CLIP** | A model with a text encoder and an image encoder trained to put matching text and images close together in one vector space |
| **Shared embedding space** | A vector space where text and images can be compared directly |
| **Vision LLM** | A chat model that accepts images in its input, e.g. Qwen on Groq or GPT-4.1 |
| **Content blocks** | The list of `{"type": "text"}` and `{"type": "image_url"}` items that make up a multimodal `HumanMessage` |
| **Base64 / data URL** | Image bytes encoded as text and sent inline as `data:image/png;base64,...` |
| **xref** | PyMuPDF's internal ID for an object (such as an image) inside the PDF |
| **`pooler_output`** | In transformers 5, the field of CLIP's feature output that holds the final projected 512-d vector |
| **Normalization** | Scaling a vector to length 1, so the dot product equals cosine similarity |
| **Modality gap** | CLIP's text vectors and image vectors sit in somewhat separate regions, so text-to-text scores beat text-to-image scores |
| **`from_embeddings`** | Building a FAISS store from vectors you already computed |
| **`similarity_search_by_vector`** | Searching a vector store with a vector instead of a text query |
| **PyMuPDF** | A fast PDF library (`import pymupdf`) for reading text, images and rendering pages |
| **Groq** | A cloud provider that serves open-weight LLMs very fast, with a free tier |
