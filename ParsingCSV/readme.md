# Parsing CSV & Excel Files for RAG — CSVLoader, Custom pandas Parsing, and Excel Sheets

This folder covers loading **tabular data** (`.csv` and `.xlsx`) into LangChain `Document` objects, which is the first stage of a RAG pipeline. The notebook compares several ways to turn rows and sheets into text that an embedding model can search:

1. **`CSVLoader`** (LangChain): one Document per CSV row, written as `column: value` lines.
2. **Custom CSV processing with pandas**: one Document per row, with content and metadata you design yourself.
3. **Custom Excel processing with pandas**: one Document per **sheet**.
4. **`UnstructuredExcelLoader`**: Unstructured's element-based Excel loader. It fails in the current environment (see [Cell 12](#cell-12-method-4-unstructuredexcelloader)).

## 1. Core Concepts

### RAG (Retrieval-Augmented Generation)
**Definition:** A technique where a Large Language Model (LLM) answers questions using information *retrieved* from your own documents, rather than relying only on what it learned during training.

**Explanation:** A RAG pipeline usually has these stages:

```
.csv / .xlsx ──► Parse ──► (Chunk) ──► Embed ──► Vector DB ──► Retrieve ──► LLM answer
                └ this folder ┘
```

With tabular data, *how you turn a table into text* matters more than with prose. A sentence still means something if you cut it out of a paragraph. The value `29.99` means nothing unless it stays next to its column name (`Price`) and its row (`Mouse`).

### Why tables are different from text
**Definition:** A table is **structured data**. Every value has a meaning that comes from its *position* (its column header and its row), not just from the value itself.

**Explanation:** Embedding models are trained on natural language, not grids. If you flatten a table into one long string (`Laptop Electronics 999.99 50 ...`), the link between `999.99` and "Price" is weakened, and the more rows you put into one chunk, the more the meanings blur together. So the main design question in this folder is:

> **What is one Document?** A single row, a whole sheet, or a group of rows?

| Granularity | Good for | Weak at |
|---|---|---|
| **One row = one Document** (CSV methods here) | Questions about a single entity: *"How much does the mouse cost?"* | Questions across rows: *"Which category has the most stock?"* |
| **One sheet = one Document** (Excel method here) | Small summary tables, giving the LLM a full overview | Large sheets (they won't fit in one chunk), precise retrieval |
| **Groups of N rows** | Medium-sized tables | Rows that belong together may be split across groups |

> **Note:** Questions like "total stock of all electronics" are *aggregation* questions. Vector search alone answers them badly, because the answer is not written in any single chunk. For those, real systems either put pre-computed summaries into the index (like the `Summary` sheet here) or let the LLM run pandas or SQL on the table instead of retrieving text.

### CSV (Comma-Separated Values)
**Definition:** A plain-text file where each line is a row and the values are separated by a **delimiter** (usually `,`). The first line is normally the **header** with the column names. Values that contain the delimiter are wrapped in a **quote character** (usually `"`).

**Explanation:** CSV has no data types, no sheets and no formatting. Everything is text, and the reader (pandas, Python's `csv` module) decides what is a number. Here is the start of `Files/products.csv`:

```csv
Product,Category,Price,Stock,Description
Laptop,Electronics,999.99,50,High-performance laptop with 16GB RAM and 512GB SSD
Mouse,Accessories,29.99,200,Wireless optical mouse with ergonomic design
```

### Excel (`.xlsx`)
**Definition:** The Office Open XML spreadsheet format. Like `.docx`, an `.xlsx` is a **ZIP archive of XML files**. Each sheet is stored in its own file (`xl/worksheets/sheet1.xml`, …).

**Explanation:** Unlike CSV, a workbook can hold **several sheets**, typed cells (numbers, dates, formulas), merged cells and formatting. A parser has to decide how to handle each sheet, and the sheet name itself (`Summary`, `Products`) is useful context to keep. The older binary `.xls` format needs a different reader (`xlrd`).

### Document (LangChain)
**Definition:** `langchain_core.documents.Document` is LangChain's basic unit of data. It has two fields:
- `page_content`: the text that gets embedded and searched (a `str`)
- `metadata`: a `dict` of extra information (source file, row number, category, …)

**Explanation:** Every method in this notebook returns a `List[Document]`. What changes between them is how many Documents you get and what goes into each field:

| Method | Documents for the sample data |
|---|---|
| `CSVLoader` | 5 (one per row) |
| Custom CSV function | 5 (one per row) |
| Custom Excel function | 2 (one per sheet) |

### `page_content` vs `metadata` for tables
**Explanation:** This split is the most important design choice for tabular data:

- **`page_content`** is what the embedding model "reads". Put the text you want to *match on semantically* here: names, descriptions, and the column labels that give numbers their meaning.
- **`metadata`** is not embedded. It is used for **exact filtering** (`category == "Electronics"`, `price < 100`) and for citations (`source`, `row`). Columns with exact values, such as IDs, categories and prices, are very useful here.

A good row-level Document often puts the same field in **both** places: the text for semantic search and the metadata for filtering. The custom CSV function in Cell 7 does exactly this.

### Cell 2: Create the sample data and save it as CSV

```python
data = {
    'Product': ['Laptop', 'Mouse', 'Keyboard', 'Monitor', 'Webcam'],
    'Category': ['Electronics', 'Accessories', 'Accessories', 'Electronics', 'Electronics'],
    'Price': [999.99, 29.99, 79.99, 299.99, 89.99],
    'Stock': [50, 200, 150, 75, 100],
    'Description': [
        'High-performance laptop with 16GB RAM and 512GB SSD',
        'Wireless optical mouse with ergonomic design',
        'Mechanical keyboard with RGB backlighting',
        '27-inch 4K monitor with HDR support',
        '1080p webcam with noise cancellation'
    ]
}

df = pd.DataFrame(data)
df.to_csv('files/products.csv', index=False)
```

**What it does:**
1. `data` is a **dict of lists**: each key is a column name, and each list holds that column's values in row order. All lists must have the same length (5).
2. `pd.DataFrame(data)` turns it into a 5 × 5 table.
3. `to_csv(..., index=False)` writes the file **without** pandas' row index (0, 1, 2, …). Without `index=False`, the CSV would get an extra unnamed first column.

The data mixes three kinds of columns, which is typical for real tables:
- **Categorical:** `Product`, `Category`
- **Numeric:** `Price`, `Stock`
- **Free text:** `Description`, the column with the most meaning for semantic search

> **Path case:** the code writes to `files/`, but the folder on disk is `Files/`. Windows paths are case-insensitive, so this works here. On Linux or macOS it would fail with `FileNotFoundError` unless the folder is renamed or the paths are changed to `Files/`.

### Cell 3: Save as an Excel workbook with two sheets

```python
with pd.ExcelWriter('files/inventory.xlsx') as writer:
    df.to_excel(writer, sheet_name='Products', index=False)

    summary_data = {
        'Category': ['Electronics', 'Accessories'],
        'Total_Items': [3, 2],
        'Total_Value': [1389.97, 109.98]
    }
    pd.DataFrame(summary_data).to_excel(writer, sheet_name='Summary', index=False)
```

**What it does:**
1. `pd.ExcelWriter` opens one workbook. Every `to_excel(writer, sheet_name=...)` call inside the `with` block adds a **sheet** to the same file. The file is saved when the block ends.
2. Sheet **`Products`** holds the same 5 rows as the CSV.
3. Sheet **`Summary`** holds a hand-written aggregate per category.

> The `Summary` numbers are typed in by hand, not calculated. `Total_Value` is the **sum of unit prices** (999.99 + 299.99 + 89.99 = 1389.97), not price × stock. If you wanted inventory value, you would calculate it, for example `df.assign(Value=df.Price * df.Stock).groupby('Category').agg(Total_Items=('Product', 'count'), Total_Value=('Value', 'sum'))`.

A summary sheet like this is useful in RAG. It is **pre-computed aggregation in plain text**, so the retriever can answer "how many electronics items are there?" without reasoning across rows.

### Cell 6: Method 1, `CSVLoader` (one row = one Document)

```python
csv_loader = CSVLoader(
    file_path='files/products.csv',
    encoding='utf-8',
    csv_args={
        'delimiter': ',',
        'quotechar': '"',
    }
)

csv_docs = csv_loader.load()

print(f"Loaded {len(csv_docs)} documents (one per row)")
print(f"Content: {csv_docs[0].page_content}")
print(f"Metadata: {csv_docs[0].metadata}")
```

**What it does:**
1. `CSVLoader` opens the file with the given `encoding` and reads it with Python's built-in **`csv.DictReader`**. `csv_args` is passed straight to `DictReader`:
   - `delimiter=','` is the character between values (use `';'` or `'\t'` for other formats).
   - `quotechar='"'` wraps values that contain the delimiter, e.g. `"Mouse, wireless"`.
2. `DictReader` uses the header line as keys, so each row becomes a dict like `{'Product': 'Laptop', 'Category': 'Electronics', ...}`.
3. For each row, the loader builds `page_content` by writing **one `key: value` line per column**.
4. `metadata` gets `source` (the file path) and `row` (the 0-based row number, not counting the header).

**Output:**
```
Loaded 5 documents (one per row)

First document:
Content: Product: Laptop
Category: Electronics
Price: 999.99
Stock: 50
Description: High-performance laptop with 16GB RAM and 512GB SSD
Metadata: {'source': 'files/products.csv', 'row': 0}
```

**Why the `key: value` format works:** every value is written next to its column name. The chunk for the laptop literally contains `Price: 999.99`, so a query like *"laptop price"* is a close match, and the LLM reading the chunk knows what each number means.

**Takeaways:**
- No pandas needed, very little code, and works for any CSV.
- Everything is a **string**. `DictReader` does no type conversion, so `Price` is `'999.99'`, not a number.
- The metadata is minimal: just `source` and `row`. You **cannot filter** by category or price unless you configure it (see below).
- All columns go into the content, including ones that may only add noise to the embedding (internal IDs, timestamps).

#### Useful `CSVLoader` parameters not used in the notebook

| Parameter | Effect |
|---|---|
| `source_column='Product'` | Uses that column's value as `metadata['source']` instead of the file path, which gives citations like "Laptop" instead of the file name. |
| `metadata_columns=['Category', 'Price']` | Copies these columns into `metadata` (and leaves them out of `page_content`), so you can filter on them. |
| `content_columns=['Product', 'Description']` | Only these columns go into `page_content`. |
| `autodetect_encoding=True` | Tries other encodings if `encoding` fails. Useful for CSVs exported from Excel on Windows (often `cp1252`). |

These parameters get you most of the way to the custom function below while still using the built-in loader:

```python
CSVLoader(
    'files/products.csv',
    encoding='utf-8',
    source_column='Product',
    metadata_columns=['Category', 'Price', 'Stock'],
)
```

### Cell 7: Method 2, custom CSV processing with pandas

```python
from typing import List
from langchain_core.documents import Document

def process_csv_intelligently(filepath: str) -> List[Document]:
    """Process CSV with intelligent document creation"""
    df = pd.read_csv(filepath)
    documents = []

    # Strategy 1: One document per row with structured content
    for idx, row in df.iterrows():
        content = f"""Product Information:
        Name: {row['Product']}
        Category: {row['Category']}
        Price: ${row['Price']}
        Stock: {row['Stock']} units
        Description: {row['Description']}"""

        doc = Document(
            page_content=content,
            metadata={
                'source': filepath,
                'row_index': idx,
                'product_name': row['Product'],
                'category': row['Category'],
                'price': row['Price'],
                'data_type': 'product_info'
            }
        )
        documents.append(doc)
    return documents
```

This cell only **defines** the function. Cell 8 calls it.

**What it does:**
1. `pd.read_csv(filepath)` loads the CSV into a DataFrame. Unlike `csv.DictReader`, pandas **infers types**: `Price` becomes `float64` and `Stock` becomes `int64`.
2. `df.iterrows()` yields `(index, row)` pairs. `row` is a pandas `Series`, so you access values by column name with `row['Price']`.
3. **The content is a template you control:**
   - A heading (`Product Information:`) tells the embedding model and the LLM what kind of record this is.
   - Labels can be renamed to friendlier words (`Product` → `Name`).
   - **Units and symbols are added** (`$999.99`, `50 units`), which makes the text closer to how users phrase questions ("how many units…", "costs $…").
4. **The metadata is rich and typed:**
   - `product_name`, `category`, `price` are copied from the row, so a vector store can filter them exactly: `filter={'category': 'Electronics'}`.
   - `price` stays a **number** (`999.99`), so range filters like `price < 100` are possible in stores that support them.
   - `data_type: 'product_info'` is a fixed tag. When one index holds several kinds of data (products, sheets, PDFs), you can filter by it.

#### The indentation gotcha

Because the f-string is triple-quoted and indented inside the function, the **leading spaces become part of the text**. The real output is:

```
'Product Information:\n        Name: Laptop\n        Category: Electronics\n ...'
```

It still works, but those spaces are noise that gets embedded and counts toward token limits. Two easy fixes:

```python
import textwrap

content = textwrap.dedent(f"""\
    Product Information:
    Name: {row['Product']}
    ...""")

# or build it line by line:
content = "\n".join([
    "Product Information:",
    f"Name: {row['Product']}",
    f"Category: {row['Category']}",
    f"Price: ${row['Price']}",
    f"Stock: {row['Stock']} units",
    f"Description: {row['Description']}",
])
```


```python
Document(
    metadata={'source': 'files/products.csv', 'row_index': 0, 'product_name': 'Laptop',
```

**Takeaways:**
- **Full control** over wording, labels, units and metadata, which makes this the best option for retrieval quality.
- Real types (numbers stay numbers) in metadata.
- The column names are **hard-coded**, so the function only works for this exact CSV layout. A reusable version would take a list of content columns and metadata columns as arguments.
- `iterrows()` is slow on large files (hundreds of thousands of rows). `df.to_dict('records')` or `itertuples()` is much faster.
- If a cell is empty, pandas reads it as `NaN`, and the text will literally say `Price: $nan`. Clean the data first with `df.fillna(...)` or `df.dropna(...)`.

### Cell 9: Method 3, Excel processing with pandas (one sheet = one Document)

```python
def process_excel_with_pandas(filepath: str) -> List[Document]:
    """Process Excel with sheet awareness"""
    documents = []

    excel_file = pd.ExcelFile(filepath)

    for sheet_name in excel_file.sheet_names:
        df = pd.read_excel(filepath, sheet_name=sheet_name)

        sheet_content = f"Sheet: {sheet_name}\n"
        sheet_content += f"Columns: {', '.join(df.columns)}\n"
        sheet_content += f"Rows: {len(df)}\n\n"
        sheet_content += df.to_string(index=False)

        doc = Document(
            page_content=sheet_content,
            metadata={
                'source': filepath,
                'sheet_name': sheet_name,
                'num_rows': len(df),
                'num_columns': len(df.columns),
                'data_type': 'excel_sheet'
            }
        )
        documents.append(doc)

    return documents
```

**What it does:**
1. `pd.ExcelFile(filepath)` opens the workbook once and exposes `.sheet_names` (`['Products', 'Summary']`) without reading the data.
2. For each sheet, `pd.read_excel(..., sheet_name=...)` loads it into a DataFrame. (This re-opens the file each time. `excel_file.parse(sheet_name)` would reuse the already-open file.)
3. The content starts with a short **header block**: sheet name, column list and row count. Even if the table text is long, the chunk begins with a description of what it holds.
4. `df.to_string(index=False)` renders the whole sheet as a **fixed-width text table**, with columns lined up using spaces.
5. The metadata records sheet-level facts (`sheet_name`, `num_rows`, `num_columns`), so you can filter for "only the Summary sheet".

**Takeaways:**
- **Sheet-aware:** each sheet's name and shape are kept, which matters for multi-sheet workbooks.
- Good for **small sheets** and summary tables. The LLM gets the whole table at once and can compare rows.
- **Does not scale:** a sheet with 10,000 rows becomes one huge Document. It must then be split, and a plain text splitter would cut the table in the middle of rows and lose the header for every chunk after the first. For large sheets, use the row-level approach from Cell 7 (with `sheet_name` added to the metadata), or split into groups of N rows and **repeat the header line in each group**.
- `to_string()` pads columns with spaces. That looks fine to a human, but it wastes tokens. `df.to_markdown(index=False)` (needs the `tabulate` package) or `df.to_csv(index=False)` are more compact, and LLMs read Markdown tables well.

## 4. Method Comparison

| | `CSVLoader` | Custom CSV (pandas) | Custom Excel (pandas) | `UnstructuredCSVLoader` / `UnstructuredExcelLoader` |
|---|---|---|---|---|
| Unit per Document | 1 row | 1 row | 1 sheet | 1 table (whole file / sheet) |
| Documents for the sample | 5 | 5 | 2 | 1 / 2 |
| Content format | `col: value` lines | Your own template (labels, units) | Header block + fixed-width table | Space-separated cells + HTML in metadata |
| Values typed? | No, all strings | Yes (pandas inference) | Yes | No |
| Metadata | `source`, `row` | Anything you choose | Sheet name, shape | File info, `category`, `text_as_html`, sheet name |
| Multiple sheets | — | — | Yes | Yes (Excel) |
| Scales to large files | Yes | Yes (use `itertuples`) | No, needs splitting | No, needs splitting |
| Effort | Lowest | Highest | Medium | Low, but heavy dependencies |
| Best for | Quick start on any CSV | Production row-level retrieval with filters | Small sheets, summaries, multi-sheet workbooks | Keeping a table whole, HTML for the LLM |

**Rule of thumb:**
- Start with **`CSVLoader`** plus `metadata_columns` / `source_column`.
- Move to a **custom pandas function** when you need better wording, real types, cleaning, or data from several sources.
- Use **sheet-level Documents** only for small or summary sheets. Index large sheets row by row.
- Answer questions that need **counting, summing or sorting across all rows** with pre-computed summary Documents or a pandas/SQL tool, not with vector search alone.

## 5. Using the Output in a RAG Pipeline

Typical next steps after this folder:

- **No chunking for rows:** a row-level Document is already small and self-contained, so you usually embed it as it is. Splitting a row with a text splitter would separate values from their labels.
- **Chunking for sheets:** if a sheet-level Document is too large, split it **by rows** and repeat the column header in every chunk, instead of using a character-based splitter.
- **Metadata filtering:** pass row metadata into the vector store so queries can combine semantic and exact matching:

  ```python
  from langchain_community.vectorstores import Chroma

  vectordb = Chroma.from_documents(docs, embedding=embeddings)
  vectordb.similarity_search("ergonomic input device", k=3,
                             filter={"category": "Accessories"})
  ```

  Chroma only accepts `str`, `int`, `float` and `bool` metadata values. pandas types such as `numpy.int64` (e.g. `row['Stock']`) should be converted with `int(...)` / `float(...)` before storing.
- **Mixing granularities:** you can index row Documents *and* the `Summary` sheet Document together. Use the `data_type` metadata key to tell them apart or filter between them.
- Then embed (e.g. `sentence-transformers` or OpenAI embeddings) and store in **ChromaDB** or **FAISS**, as in the other folders of this repo. For text splitters, see [../DataIngestion/readme.md](../DataIngestion/readme.md).

## 7. Quick Glossary

| Term | Meaning |
|---|---|
| **CSV** | Plain-text table: one row per line, values separated by a delimiter, first line is the header. |
| **Delimiter** | The character between values (`,`, `;`, `\t`). |
| **Quote character** | Wraps a value that contains the delimiter, e.g. `"a, b"`. |
| **.xlsx** | A ZIP of XML files (Office Open XML) holding a workbook with one or more sheets. |
| **Sheet** | One table (tab) inside an Excel workbook. |
| **DataFrame** | pandas' in-memory table with named, typed columns. |
| **`iterrows()`** | pandas method that loops over a DataFrame as `(index, row)` pairs. |
| **Document** | LangChain object with `page_content` + `metadata`. |
| **Document Loader** | A class that turns a file into `List[Document]` through `.load()`. |
| **Granularity** | How much data goes into one Document: a row, a group of rows, or a sheet. |
| **Metadata filtering** | Restricting a vector search to Documents whose metadata matches exact values, e.g. `category == "Accessories"`. |
| **Aggregation query** | A question that needs a calculation across many rows (sum, count, max). Vector search alone handles these poorly. |
| **`text_as_html`** | An HTML version of a table that Unstructured stores in metadata so the structure isn't lost. |
